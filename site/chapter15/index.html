    Chapter 15: 최종 점검 - 한눈에 보는 데이터와 나¶

    🎯 이 장에서 배우는 것¶

    • 압축, 암호화, 빅데이터, 전처리, 시각화의 핵심 개념을 한 문장으로 설명할 수 있다.
    • 데이터 수집 → 전처리 → 분석 → 시각화의 전체 흐름을 순서대로 설명할 수 있다.
    • 개념 간의 연결 관계를 파악하여 각 단계가 왜 필요한지 이유를 말할 수 있다.
    • 성취기준별 자기 점검 체크리스트로 부족한 부분을 스스로 확인하고 보완할 수 있다.

    💡 왜 이걸 배우나요?¶

    여러분은 지금까지 꽤 긴 여정을 함께 했습니다. 데이터를 작게 만드는 압축, 데이터를 안전하게 지키는 암호화, 세상에 넘치는 빅데이터, 쓸 만한 데이터로 다듬는 전처리, 그리고 숫자에서 의미를 꺼내는 시각화까지.

    그런데 이것들이 서로 따로 노는 기술일까요? 아닙니다. 마치 요리처럼, 재료를 구해서 → 손질하고 → 조리하고 → 예쁘게 담아내는 하나의 흐름입니다.

    이 장은 새로운 내용을 배우는 장이 아닙니다. 지금까지 배운 모든 것을 하나의 그림으로 연결하고, 내가 무엇을 알고 무엇을 모르는지 스스로 확인하는 시간입니다.

    🧠 알아보기: 공부를 잘하는 학생과 못하는 학생의 차이 중 하나는 "내가 무엇을 모르는지 아는 능력"입니다. 이것을 메타인지라고 합니다. 이 장은 여러분의 메타인지를 키우는 시간입니다.

    📚 핵심 개념¶

    개념 1: 데이터 관리 - 압축과 암호화¶

    비유로 시작

    여행 가방을 생각해보세요. 옷을 그냥 넣으면 부피가 크지만, 돌돌 말아서 넣으면(압축) 훨씬 많은 옷이 들어갑니다. 그리고 중요한 물건은 자물쇠가 달린 파우치에 넣어두죠(암호화). 압축은 부피를 줄이는 것, 암호화는 안전하게 잠그는 것입니다.

    정확한 정의

    • 압축(Compression): 데이터에서 반복되거나 예측 가능한 패턴을 찾아 더 적은 용량으로 표현하는 기술. 손실 압축(JPEG, MP3)과 무손실 압축(ZIP, PNG)으로 나뉩니다.
    • 암호화(Encryption): 데이터를 특정 규칙(키)으로 변환하여 권한 없는 사람은 내용을 알 수 없도록 만드는 기술. 대칭키 방식과 공개키 방식이 있습니다.

    예시로 확인

    graph LR A[원본 데이터\n100MB 사진] --> B[압축\n손실/무손실] B --> C[압축 파일\n20MB] C --> D[암호화\n키 적용] D --> E[🔒 암호화된\n전송 파일] E --> F[복호화\n키 적용] F --> G[복원된 파일\n수신자만 확인]

    💡 핵심 구분: 압축은 크기를 줄이는 것, 암호화는 내용을 숨기는 것. 둘을 동시에 적용할 수 있습니다(먼저 압축 → 그 다음 암호화).

    개념 2: 빅데이터 - 세상의 데이터를 이해하기¶

    비유로 시작

    도서관에 책이 1억 권 있다고 상상해보세요. 일반 도서관 관리 방식으로는 책을 찾는 것도, 정리하는 것도 불가능합니다. 빅데이터도 마찬가지입니다. 기존 방법으로는 처리할 수 없을 만큼 크고, 빠르고, 다양한 데이터입니다.

    정확한 정의

    빅데이터는 3V로 특징을 설명합니다.

    • Volume(양): 테라바이트, 페타바이트 단위의 방대한 양
    • Velocity(속도): 실시간으로 빠르게 생성되고 처리되어야 하는 속도
    • Variety(다양성): 텍스트, 이미지, 음성, 영상 등 다양한 형태
    mindmap root((빅데이터)) 3V 특징 Volume 양 Velocity 속도 Variety 다양성 수집 방법 센서 데이터 소셜미디어 로그 파일 설문/거래 기록 활용 분야 의료 진단 날씨 예측 추천 시스템 교통 최적화

    예시로 확인

    여러분이 유튜브를 하루에 1시간 보면, 유튜브는 여러분이 언제, 무엇을, 얼마나, 어디서 봤는지 모두 기록합니다. 전 세계 수십억 명의 이런 데이터가 모이면 빅데이터가 됩니다. 이 데이터로 유튜브는 여러분에게 딱 맞는 영상을 추천하는 것이죠.

    개념 3: 전처리 - 데이터를 쓸 수 있게 다듬기¶

    비유로 시작

    요리를 할 때 채소를 그냥 냄비에 넣지 않죠. 씻고, 껍질을 벗기고, 적당한 크기로 자릅니다. 데이터 전처리도 똑같습니다. 수집된 날것의 데이터를 분석할 수 있는 형태로 다듬는 과정입니다.

    정확한 정의

    전처리(Preprocessing)란 수집된 원시 데이터(raw data)에서 결측값 처리, 이상값 제거, 데이터 변환, 정규화를 통해 분석에 적합한 형태로 만드는 과정입니다.

    flowchart TD A[원시 데이터 수집] --> B{데이터 점검} B --> C[결측값 처리\n빠진 값 채우기/제거] B --> D[이상값 처리\n비정상적 값 수정] B --> E[중복 제거\n같은 데이터 정리] C --> F[데이터 변환\n형식 통일] D --> F E --> F F --> G[정규화/표준화\n범위 맞추기] G --> H[✅ 분석 가능한\n깨끗한 데이터]

    예시로 확인

    학교 성적 데이터를 수집했더니 이런 문제들이 있었습니다.

    • 이름이 "김민준"과 "김 민준"으로 두 번 기록됨 → 중복/형식 오류
    • 국어 점수가 비어 있음 → 결측값
    • 수학 점수가 999점으로 기록됨 → 이상값
    • 점수가 어떤 곳은 100점 만점, 어떤 곳은 10점 만점 → 단위 불일치

    이런 문제를 모두 해결하는 것이 전처리입니다.

    개념 4: 시각화 - 숫자에서 이야기 꺼내기¶

    비유로 시작

    숫자로만 가득 찬 스프레드시트와 색깔이 있는 그래프 중 어느 것이 더 빨리 이해됩니까? 당연히 그래프입니다. 시각화는 복잡한 데이터를 눈으로 바로 이해할 수 있게 바꾸는 기술입니다.

    정확한 정의

    데이터 시각화(Data Visualization)란 숫자, 텍스트 형태의 데이터를 그래프, 차트, 지도 등 시각적 요소로 표현하여 패턴, 추세, 이상 징후를 직관적으로 파악하게 하는 기술입니다.

    예시로 확인

    어떤 그래프를 써야 할까요?

    • 막대 그래프: 항목 간 비교 (학교별 학생 수)
    • 꺾은선 그래프: 시간에 따른 변화 (월별 기온 변화)
    • 원 그래프: 전체에서 각 부분의 비율 (설문 응답 비율)
    • 산점도: 두 변수 간의 관계 (공부 시간과 성적의 관계)
    • 히트맵: 복잡한 패턴 한눈에 보기 (요일·시간대별 혼잡도)

    ⚠️ 생각해보기: 시각화는 데이터를 "예쁘게" 만드는 것이 아닙니다. 올바른 그래프를 선택하는 것이 핵심입니다. 잘못된 그래프는 오해를 만들 수 있습니다.

    🔨 따라하기: 전체 흐름 실습¶

    지금까지 배운 4가지 개념이 실제로 어떻게 하나의 흐름으로 연결되는지 파이썬 코드로 확인해봅시다.

    Step 1: 환경 준비¶

    # 필요한 라이브러리 불러오기
import pandas as pd
import matplotlib.pyplot as plt
import matplotlib.font_manager as fm
import hashlib
import zlib

# 한글 폰트 설정 (matplotlib)
plt.rcParams['font.family'] = 'Malgun Gothic'
plt.rcParams['axes.unicode_minus'] = False

print("✅ 환경 준비 완료!")

    Step 2: 원시 데이터 만들기 (수집 단계)¶

    # 학생 성적 원시 데이터 (현실에서는 파일이나 DB에서 읽어옵니다)
raw_data = {
    '이름': ['김민준', '이서아', '박준서', '김민준', '최하은', '정우진', None],
    '국어': [85, 92, None, 85, 78, 105, 88],
    '수학': [90, 88, 76, 90, 82, 95, 70],
    '영어': [78, 95, 83, 78, 91, 88, 85]
}

df = pd.DataFrame(raw_data)
print("📊 원시 데이터:")
print(df)
print(f"\n데이터 크기: {df.shape[0]}행 × {df.shape[1]}열")

    Step 3: 전처리하기 (전처리 단계)¶

    # 1단계: 중복 제거
df = df.drop_duplicates()
print(f"중복 제거 후: {df.shape[0]}행")

# 2단계: 결측값 처리 (이름이 없는 행 제거, 국어 점수는 평균으로 채우기)
df = df.dropna(subset=['이름'])          # 이름 없는 행 삭제
df['국어'] = df['국어'].fillna(df['국어'].mean())  # 국어 결측값 → 평균

# 3단계: 이상값 처리 (점수 범위: 0~100)
df = df[df['국어'] <= 100]

# 결과 확인
df = df.reset_index(drop=True)
print("\n✅ 전처리 완료된 데이터:")
print(df)

    Step 4: 시각화하기 (시각화 단계)¶

    # 학생별 과목 점수 막대 그래프
fig, axes = plt.subplots(1, 2, figsize=(12, 5))

# 왼쪽: 학생별 평균 점수
avg_scores = df[['국어', '수학', '영어']].mean()
axes[0].bar(avg_scores.index, avg_scores.values, color=['#FF6B6B', '#4ECDC4', '#45B7D1'])
axes[0].set_title('과목별 평균 점수', fontsize=14, fontweight='bold')
axes[0].set_ylabel('점수')
axes[0].set_ylim(0, 100)
for i, v in enumerate(avg_scores.values):
    axes[0].text(i, v + 1, f'{v:.1f}', ha='center', fontsize=11)

# 오른쪽: 학생별 총점 비교
df['총점'] = df['국어'] + df['수학'] + df['영어']
axes[1].barh(df['이름'], df['총점'], color='#96CEB4')
axes[1].set_title('학생별 총점 비교', fontsize=14, fontweight='bold')
axes[1].set_xlabel('총점')

plt.tight_layout()
plt.savefig('result.png', dpi=150, bbox_inches='tight')
plt.show()
print("✅ 시각화 완료! result.png 저장됨")

    Step 5: 압축 체험하기 (압축 단계)¶

    # 데이터를 문자열로 변환 후 압축 체험
data_str = df.to_csv(index=False).encode('utf-8')
compressed = zlib.compress(data_str, level=9)

original_size = len(data_str)
compressed_size = len(compressed)
ratio = (1 - compressed_size / original_size) * 100

print(f"📦 압축 전 크기: {original_size} bytes")
print(f"📦 압축 후 크기: {compressed_size} bytes")
print(f"📦 압축률: {ratio:.1f}% 감소")

    Step 6: 간단한 해시 암호화 체험 (암호화 단계)¶

    # 학생 이름을 해시로 변환하여 익명화 (개인정보 보호)
def anonymize(name):
    return hashlib.sha256(name.encode()).hexdigest()[:8]

df['익명ID'] = df['이름'].apply(anonymize)
print("\n🔒 익명화된 데이터 (개인정보 보호):")
print(df[['익명ID', '국어', '수학', '영어', '총점']])
print("\n✅ 전체 흐름 실습 완료!")

    ⚠️ 자주 하는 실수¶

    실수 1: 압축과 암호화를 같은 것으로 혼동

    압축은 크기를 줄이는 것, 암호화는 내용을 숨기는 것입니다. ZIP 파일은 압축이지만 암호화는 아닙니다. 비밀번호를 걸어야 암호화가 됩니다. 두 기능은 목적이 전혀 다릅니다.

    실수 2: 전처리를 나중에 해도 된다고 생각

    "일단 분석하고 나중에 데이터 정리하면 되지 않나?"라고 생각할 수 있습니다. 하지만 더러운 데이터로 분석하면 결과 자체가 잘못됩니다. "Garbage In, Garbage Out(쓰레기를 넣으면 쓰레기가 나온다)"은 데이터 분야의 철칙입니다. 전처리는 반드시 분석 전에 해야 합니다.

    실수 3: 시각화에서 그래프 종류를 아무거나 선택

    막대 그래프로 시간 변화를 표현하거나, 원 그래프로 너무 많은 항목을 표현하면 오히려 이해가 어려워집니다. 데이터의 목적과 구조에 맞는 그래프를 선택하는 것이 핵심입니다.

    실수 4: 빅데이터 = 그냥 데이터가 많은 것으로만 생각

    빅데이터는 단순히 양이 많은 것이 아닙니다. 처리 속도(Velocity)와 형태의 다양성(Variety)도 함께 봐야 합니다. 1억 개의 같은 숫자도 빅데이터라고 부를 수 있지만, 진짜 빅데이터 문제는 실시간성과 다양성에서 어렵습니다.

    실수 5: 결측값을 무조건 평균으로 채우는 것이 정답이라고 생각

    결측값 처리 방법은 상황에 따라 다릅니다. 행을 삭제할 수도 있고, 평균·중앙값으로 채울 수도 있고, 이전 값을 복사할 수도 있습니다. 어떤 방법이 맞는지는 데이터의 성격과 분석 목적에 따라 결정해야 합니다.

    📌 핵심 개념 최종 요약¶

    압축 - 데이터 용량을 줄이는 기술 - 손실(JPEG, MP3) vs 무손실(ZIP, PNG)

    암호화 - 데이터를 안전하게 보호하는 기술 - 대칭키(같은 키 사용) vs 공개키(두 가지 키 사용)

    빅데이터 - 3V: Volume(양), Velocity(속도), Variety(다양성) - 기존 방법으로 처리 불가능한 규모의 데이터

    전처리 - 결측값 처리 → 이상값 제거 → 중복 제거 → 정규화 - "Garbage In, Garbage Out" - 분석 전에 반드시 수행

    시각화 - 데이터 목적에 맞는 그래프 선택이 핵심 - 막대(비교) / 꺾은선(변화) / 원(비율) / 산점도(관계)
