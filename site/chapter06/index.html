    Chapter 06. 데이터 다듬기 ② - 선택하고 변환하기¶

    🎯 이 장에서 배우는 것¶

    • 분석 목적에 맞게 필요한 열(속성)을 선택하고 불필요한 열을 제거할 수 있다.
    • 오렌지3의 Select Columns 위젯으로 열을 골라낼 수 있다.
    • 오렌지3의 Edit Domain 위젯으로 데이터 유형을 확인하고 변환할 수 있다.
    • 전처리 전후 데이터를 비교하여 달라진 점을 설명할 수 있다.
    • 파이썬 코드로 열 선택과 데이터 타입 변환을 수행할 수 있다.

    💡 왜 이걸 배우나요?¶

    마트에서 장을 볼 때를 상상해 보세요. 냉장고에 있는 재료를 확인하지 않고 눈에 띄는 것을 모두 장바구니에 담으면 어떻게 될까요? 필요 없는 물건이 가득 차서 정작 필요한 것을 놓치거나, 계산대에서 한참을 기다려야 합니다.

    데이터 분석도 똑같습니다. 수십 개의 열이 있는 데이터를 처음부터 전부 다루려고 하면 분석이 복잡해지고, 오히려 중요한 패턴을 놓치기 쉽습니다. "필요한 것만 골라내는 능력" 이 바로 좋은 데이터 분석가의 첫 번째 습관입니다.

    이번 장에서는 오렌지3 도구와 파이썬 코드 두 가지 방법으로 다음을 익힙니다.

    • 📌 열 선택: 분석에 필요한 열만 남기기
    • 🔄 타입 변환: 숫자처럼 보이지만 범주형인 데이터 올바르게 고치기
    • 🔍 전후 비교: 처리 전과 후를 나란히 놓고 확인하기

    📚 핵심 개념¶

    개념 1: 열(Column)이란 무엇인가?¶

    비유로 시작

    학교 생활기록부를 떠올려 보세요. 생활기록부에는 이름, 학번, 국어 성적, 영어 성적, 수학 성적, 출결 현황, 특기사항 등 다양한 항목이 있습니다. 여기서 각 항목(이름, 성적, 출결 등)이 바로 데이터에서 말하는 열(Column) 입니다. 반면 각 학생 한 명의 정보 전체가 행(Row) 이 됩니다.

    정확한 정의

    데이터에서 열(Column) 은 같은 종류의 정보를 모아놓은 세로 방향의 묶음입니다. 다른 말로 속성(Attribute), 변수(Variable), 피처(Feature) 라고도 부릅니다. 오렌지3에서는 주로 속성(Attribute) 이라는 표현을 사용합니다.

    예시로 확인

    학생 성적 데이터가 있다고 가정해 봅시다.

    • 열의 종류: 학번, 이름, 국어, 영어, 수학, 출결일수, 학급코드
    • 전체 열 수: 7개
    • 분석 목적: "수학 성적이 높은 학생의 특징 파악"
    • 필요한 열: 학번, 수학, 출결일수 (3개만으로 충분할 수 있음)
    • 제거 가능한 열: 이름(개인정보), 국어·영어(분석 목적과 무관), 학급코드(불필요)

    💡 알아보기: 열을 줄이면 분석 속도가 빨라지고, 불필요한 정보로 인한 혼란을 줄일 수 있습니다. 이를 차원 축소(Dimensionality Reduction) 의 가장 기본적인 형태라고 합니다.

    개념 2: 데이터 타입 - 숫자형 vs 범주형¶

    비유로 시작

    온도계로 측정한 기온(18.5℃, 22.3℃, 30.1℃)과 날씨 상태(맑음, 흐림, 비)는 근본적으로 다른 종류의 정보입니다. 기온은 계산이 가능하고(평균, 합계 등), 날씨 상태는 그룹을 나누는 데 쓰입니다. 데이터도 이처럼 그 성질에 따라 타입을 구분해야 합니다.

    정확한 정의

    수치형(Numeric): 덧셈, 평균 같은 수학적 연산이 의미 있는 데이터 범주형(Categorical): 몇 가지 그룹 중 하나에 속하는 데이터. 계산보다 분류에 사용

    graph LR A[데이터 타입] --> B[수치형 Numeric] A --> C[범주형 Categorical] B --> D["예: 키, 몸무게, 점수, 가격"] C --> E["예: 성별, 혈액형, 지역명, 등급"] C --> F["숫자처럼 보이지만 범주형인 경우"] F --> G["예: 우편번호 '04524', 학급코드 '1반'"]

    예시로 확인

    타입을 잘못 설정하면 어떤 문제가 생길까요?

    • 우편번호 04524를 수치형으로 처리하면? → 우편번호의 평균을 계산하는 말도 안 되는 상황이 생깁니다.
    • 성별 1(남), 2(여)를 수치형으로 처리하면? → "평균 성별은 1.5입니다"라는 의미 없는 결과가 나옵니다.

    ⚠️ 생각해보기: 학급 번호(1반, 2반, 3반)를 숫자 1, 2, 3으로 저장했다면 이것은 수치형일까요, 범주형일까요? 정답은 범주형입니다. 학급 번호를 더하거나 평균 내는 것은 의미가 없으니까요.

    개념 3: Select Columns 위젯 - 열을 골라내는 도구¶

    비유로 시작

    마치 체를 이용해 모래에서 돌을 걸러내듯, Select Columns 위젯은 전체 열 중에서 원하는 열만 통과시키는 필터 역할을 합니다.

    정확한 정의

    오렌지3의 Select Columns 위젯은 데이터에서 원하는 열을 선택하거나 제거하는 위젯입니다. 드래그 앤 드롭 방식으로 직관적으로 열을 이동할 수 있습니다.

    위젯의 주요 영역 구성

    graph TD A["Select Columns 위젯"] --> B["왼쪽 패널: 사용 가능한 변수\n(Available Variables)"] A --> C["오른쪽 패널: 선택된 변수\n(Selected Variables)"] C --> D["Features: 분석에 사용할 속성"] C --> E["Target: 예측 목표 변수"] C --> F["Meta: 참고용 변수 (분석에 미포함)"]
    • Features(피처): 분석의 입력값으로 사용할 열들
    • Target(타깃): 예측하거나 분류하려는 목표 열 (예: 합격/불합격)
    • Meta(메타): 분석에는 포함하지 않지만 참고용으로 유지하는 열 (예: 학생 이름)
    • Ignored(무시): 완전히 제외할 열

    개념 4: Edit Domain 위젯 - 데이터 타입을 바로잡는 도구¶

    비유로 시작

    여권에 생년월일이 잘못 기재되어 있다면, 여권 자체의 내용은 맞지만 기재 방식이 틀린 것입니다. Edit Domain 위젯은 데이터의 값은 그대로 두고, 그 값이 어떤 종류인지를 올바르게 고쳐주는 도구입니다.

    정확한 정의

    Edit Domain 위젯은 각 열의 이름, 데이터 타입, 값의 순서 등을 편집하는 위젯입니다. 특히 수치형으로 잘못 인식된 범주형 데이터를 올바른 타입으로 변환할 때 유용합니다.

    할 수 있는 일

    • 열 이름 변경 (예: col_1 → 성별)
    • 데이터 타입 변경 (수치형 ↔ 범주형 ↔ 문자열)
    • 범주형 값의 순서 재정렬 (예: 소 < 중 < 대)
    • 특정 값을 결측치(NaN)로 처리

    💡 알아보기: Select Columns가 "어떤 열을 쓸까?"를 정하는 도구라면, Edit Domain은 "그 열을 어떻게 해석할까?"를 정하는 도구입니다. 두 위젯은 자주 함께 사용됩니다.

    🔨 따라하기¶

    이번 실습에서는 오렌지3에 내장된 Iris(붓꽃) 데이터셋을 사용합니다. Iris 데이터는 붓꽃의 꽃잎·꽃받침 크기를 측정한 데이터로, 150개의 행과 5개의 열로 구성되어 있습니다.

    📌 실습 목표: Iris 데이터에서 분석에 필요한 열만 선택하고, 타입이 올바른지 확인한 후, 전처리 전후 데이터를 나란히 비교합니다.

    Step 1: 오렌지3 실행 및 데이터 불러오기¶

    1. 오렌지3를 실행합니다.
    2. 왼쪽 위젯 패널에서 Data 탭을 클릭합니다.
    3. Datasets 위젯을 캔버스로 드래그합니다.
    4. Datasets 위젯을 더블클릭하여 열면 데이터셋 목록이 나타납니다.
    5. 검색창에 iris를 입력하고 Iris 데이터셋을 선택합니다.
    6. 우측 하단의 Send 버튼을 클릭합니다.

    ✅ 확인: 위젯 아래에 "150 instances, 5 features"라는 메시지가 표시되면 데이터가 올바르게 불러와진 것입니다.

    Step 2: Data Table로 원본 데이터 확인하기¶

    1. Data 탭에서 Data Table 위젯을 캔버스에 추가합니다.
    2. Datasets 위젯의 출력 포트(오른쪽 점)에서 Data Table 위젯의 입력 포트(왼쪽 점)로 선을 연결합니다.
    3. Data Table을 더블클릭하여 데이터를 살펴봅니다.

    Iris 데이터의 열 구성을 확인합니다.

    • sepal length: 꽃받침 길이 (수치형)
    • sepal width: 꽃받침 너비 (수치형)
    • petal length: 꽃잎 길이 (수치형)
    • petal width: 꽃잎 너비 (수치형)
    • iris: 붓꽃 품종 (범주형 - Target)

    💡 생각해보기: 만약 분석 목적이 "꽃잎 크기만으로 품종을 구분할 수 있을까?"라면, 어떤 열이 필요하고 어떤 열이 불필요할까요?

    Step 3: Select Columns 위젯으로 열 선택하기¶

    1. Data 탭에서 Select Columns 위젯을 캔버스에 추가합니다.
    2. Datasets 위젯 → Select Columns 위젯 순으로 연결합니다.
    3. Select Columns 위젯을 더블클릭하여 설정 창을 엽니다.

    설정 방법

    오른쪽 Features 영역에는 현재 모든 수치형 열이 있습니다. 분석 목적(꽃잎 크기로 품종 구분)에 맞게 다음과 같이 변경합니다.

    • Features 유지: petal length, petal width
    • Ignored(제거)로 이동: sepal length, sepal width
    • 제거할 열을 클릭하여 선택한 후 왼쪽 화살표 버튼(←) 또는 드래그로 왼쪽 패널(Available Variables)로 이동합니다.
    • Target 유지: iris (품종 - 이미 Target으로 설정되어 있음)

    ✅ 확인: 오른쪽 Features에 petal length, petal width 두 개, Target에 iris 한 개만 남아 있으면 올바르게 설정된 것입니다.

    Step 4: Edit Domain으로 타입 확인하기¶

    1. Data 탭에서 Edit Domain 위젯을 캔버스에 추가합니다.
    2. Select Columns 위젯 → Edit Domain 위젯 순으로 연결합니다.
    3. Edit Domain 위젯을 더블클릭합니다.

    타입 확인 및 변환 실습

    왼쪽 변수 목록에서 각 열을 클릭하면 오른쪽에 해당 열의 정보가 표시됩니다.

    • petal length 클릭 → Numeric(수치형) 으로 표시됨 ✅
    • petal width 클릭 → Numeric(수치형) 으로 표시됨 ✅
    • iris 클릭 → Categorical(범주형) 으로 표시됨 ✅

    Iris 데이터는 이미 타입이 올바르게 설정되어 있습니다. 이번에는 의도적으로 타입 변환을 체험해 봅니다.

    범주형으로 변환 연습

    1. 왼쪽 목록에서 petal length를 클릭합니다.
    2. 오른쪽 Type 드롭다운을 Numeric → Categorical 로 변경합니다.
    3. 아래 Apply 버튼을 클릭합니다.
    4. 변화를 확인한 후 다시 Numeric 으로 되돌리고 Apply를 누릅니다.

    ⚠️ 주의: 실제 분석에서는 타입을 신중하게 변환해야 합니다. 연습 후 반드시 원래 타입으로 돌려놓으세요.

    Step 5: 전후 비교 - 두 개의 Data Table 나란히 보기¶

    전처리 전과 후를 직접 비교합니다.

    1. Data Table 위젯을 하나 더 캔버스에 추가합니다. (총 2개)
    2. 첫 번째 Data Table: Datasets 위젯에 연결 (원본 데이터)
    3. 두 번째 Data Table: Edit Domain 위젯에 연결 (전처리 후 데이터)
    4. 두 Data Table을 나란히 열어서 비교합니다.
    graph LR A["Datasets\n(Iris 원본)"] --> B["Data Table 1\n원본: 5개 열"] A --> C["Select Columns\n열 선택"] C --> D["Edit Domain\n타입 확인"] D --> E["Data Table 2\n처리 후: 3개 열"]

    비교 결과 확인

    • Data Table 1 (원본): sepal length, sepal width, petal length, petal width, iris → 5개 열
    • Data Table 2 (처리 후): petal length, petal width, iris → 3개 열

    💡 정리하기: 불필요한 열 2개(sepal length, sepal width)가 제거되어 데이터가 간결해졌습니다. 분석 목적에 맞는 핵심 정보만 남았습니다.

    Step 6: 파이썬으로 같은 작업 해보기¶

    오렌지3의 GUI로 한 작업을 파이썬 코드로도 수행할 수 있습니다. 아래 코드를 파이썬 환경(Jupyter Notebook 또는 코랩)에서 실행해 보세요.

    📝 전체 코드¶

    # 필요한 라이브러리 불러오기
import pandas as pd
from sklearn.datasets import load_iris

# ① 데이터 불러오기
iris_data = load_iris()
df = pd.DataFrame(iris_data.data, columns=iris_data.feature_names)
df['species'] = iris_data.target  # 0: setosa, 1: versicolor, 2: virginica

print("=== 원본 데이터 ===")
print(f"행 수: {df.shape[0]}, 열 수: {df.shape[1]}")
print(df.head())
print()

# ② 데이터 타입 확인 (Edit Domain과 같은 역할)
print("=== 각 열의 데이터 타입 ===")
print(df.dtypes)
print()

# ③ 열 선택하기 (Select Columns와 같은 역할)
# 분석 목적: 꽃잎 크기만으로 품종 구분
selected_columns = ['petal length (cm)', 'petal width (cm)', 'species']
df_selected = df[selected_columns]

print("=== 열 선택 후 데이터 ===")
print(f"행 수: {df_selected.shape[0]}, 열 수: {df_selected.shape[1]}")
print(df_selected.head())
print()

# ④ 타입 변환하기: species를 범주형으로 변환
# (Edit Domain에서 Numeric → Categorical로 변환하는 것과 같음)
df_selected = df_selected.copy()
df_selected['species'] = df_selected['species'].astype('category')

print("=== 타입 변환 후 ===")
print(df_selected.dtypes)
print()
print(f"species 범주 목록: {df_selected['species'].cat.categories.tolist()}")

# ⑤ 전후 비교 요약
print("=== 전처리 전후 비교 ===")
print(f"처리 전: {df.shape[1]}개 열 → 처리 후: {df_selected.shape[1]}개 열")
print(f"제거된 열: {set(df.columns) - set(df_selected.columns)}")

    💡 코드 핵심 정리 - df[열_목록] → 원하는 열만 선택 (Select Columns와 동일) - .dtypes → 각 열의 데이터 타입 확인 (Edit Domain과 동일) - .astype('category') → 범주형으로 타입 변환 - .astype('float') → 수치형으로 타입 변환

    ⚠️ 자주 하는 실수¶

    실수 1: 분석 목적 없이 무조건 열을 제거한다

    "열이 많으면 복잡하니까 그냥 절반만 남길게요"라는 식의 접근은 위험합니다. 중요한 특징을 담은 열을 실수로 제거하면 분석 결과가 완전히 달라질 수 있습니다. 열을 제거하기 전에 항상 "이 열이 분석 목적에 어떤 역할을 하는가?" 를 먼저 생각하세요.

    실수 2: 숫자로 저장된 범주형 데이터를 그냥 둔다

    성별(1=남, 2=여), 학급 번호(1, 2, 3), 우편번호처럼 숫자로 표현되었지만 실제로는 범주형인 데이터를 수치형으로 두면, 알고리즘이 "2반이 1반보다 크다"거나 "성별 평균이 1.5"라는 잘못된 계산을 할 수 있습니다. Edit Domain이나 .astype('category')로 반드시 변환하세요.

    실수 3: Select Columns에서 Meta와 Ignored의 차이를 혼동한다

    • Ignored: 데이터에서 완전히 제외됩니다. 다음 위젯으로 전달되지 않습니다.
    • Meta: 분석 계산에는 포함되지 않지만, 데이터는 유지됩니다. 나중에 결과를 식별할 때(예: 학생 이름) 활용할 수 있습니다.

    학생 이름처럼 "분석엔 불필요하지만 결과 확인에는 필요한" 열은 Ignored가 아닌 Meta로 설정해야 합니다.

    실수 4: 전처리 후 데이터를 확인하지 않는다

    Select Columns와 Edit Domain을 설정한 후 결과를 Data Table로 바로 확인하지 않는 경우가 많습니다. 설정이 의도대로 적용되었는지 반드시 Data Table에서 눈으로 확인하는 습관을 들이세요. 실수를 일찍 발견할수록 수정이 쉽습니다.
